## 测量与归因

原先的 44.4 → 34.0 ms 来自每组 5 次的合成探针。本轮对照使用同一机器、同一文档和同步派生回调，每个场景预热 8 次、采样 21 次，同时报告中位数与 P90。计时包括修改叶块、更新 DOM、提交操作，以及 Markdown、字数、内容签名和目录计算；初始化、选区设置、帧等待和正确性检查均在计时外。

每次采样后，缓存输出都与独立完整序列化结果比较；插入、撤销和重做还核对前后文档。测量覆盖段落和标题的首部、中部、尾部编辑，以及结构插入、撤销和重做。`plain` 数据用于前后对比；带包装器及 CPU profiler 的数据仅用于归因，不混入普通延迟统计。

深度采样改变了对历史阶段的解释：`History._record` 的约 21–24 ms 主要来自读取原生 `Selection.anchorNode`，OT 反演及合并本身很小。原合成探针在替换文档后没有选区；CDP 时间线确认空选区读取触发了同步 `UpdateLayoutTree` 和 `Layout`，三次分别合计约 24.4、28.6、31.2 ms，`partialLayout=false`，布局对象总数为 244,328。

独立选区实验中，有折叠光标、正向或反向选择时，`anchorNode` 与 Range 端点读取开销接近计时分辨率。先读空选区的 `rangeCount` 同样触发布局，而 `Selection.direction` 在有选区时也触发布局，因此没有修改现有选区读取。最终分别保留空选区原探针和有光标的同路径合成采样；两者均不是物理按键到屏幕绘制的延迟。

## 落地修改

1. **历史复用内部状态版本。** JSON1 修改路径时保留未变节点；历史直接读取内部版本，不再在普通编辑和撤销入口复制全文。插入操作及外部传入状态仍复制以隔离可变 DOM 元数据。公共事件的 `prevDoc` 和 `doc` 仅在读取时各自复制，保留前后版本和相互独立的可变副本。
2. **缓存未变根块的 Markdown 片段。** 缓存同时校验前块、空行、列表标记及松紧上下文；修改后的列表、表格等容器整体重新序列化，确保编号、缩进和列宽一致。更改列表缩进时重建序列化器；任意外部可变状态继续使用完整序列化路径。
3. **单次扫描字数。** 去掉全文拆分、去除汉字和 token 数组，保留原有 UTF-16、汉字区间及 ECMAScript 空白规则，包括汉字移除后连接拉丁词的行为。ASCII 字符快速返回，避免逐字检查全部 Unicode 空白范围。
4. **减少块路径查询的数组分配。** 链表 `offset` 找到节点即停止；`find` 从较近的头或尾步进。保留非法索引的原返回行为，无需新增结构失效缓存。

## 复测

在 `packages/muya/e2e` 中启动开发宿主：

```powershell
node ../../../node_modules/vite/bin/vite.js --host 127.0.0.1 --port 5174 --strictPort
```

另一终端回到仓库根目录，分别测量两种选区情况：

```powershell
node docs/audit-20261011/performance-study.mjs result-empty.json --counts=10000 --samples=21 --warmup=8 --mode=plain --selection=empty
node docs/audit-20261011/performance-study.mjs result-caret.json --counts=10000 --samples=21 --warmup=8 --mode=plain --selection=caret
```

省略 `--mode=plain` 可增加嵌套阶段归因和独立快照复制测量；`--profile-only` 可采集短 CPU profile。`selection-study.mjs` 和 `selection-layout-study.mjs` 分别复现选区读取和布局归因。
