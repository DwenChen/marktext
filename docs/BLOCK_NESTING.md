# 在此层级嵌套块格式

## 在已有层级之间继续键入（1.2.0）

右键新增 **在上一层级键入**、**在下一层级键入**。这两个入口只在检测到对应层级时显示；有文字选区时隐藏。

例如，光标在下面的“子条目”末尾时，Enter 会继续生成二级条目。选择 **在上一层级键入**，可直接进入一级列表的下一条：

```markdown
- 父条目
  - 子条目
- 在这里继续键入一级条目
- 原来的其他一级条目
```

- **上一层级**：每次退出一个块格式层级，在父列表中新增条目，或在父引用中新增段落。从顶层列表或引用退出，会在正文中创建普通段落。原条目的文字和子块全部保留。
- **下一层级**：只进入当前条目或引用中已经存在的子块。优先选择光标后最近的子块；后方没有时，选择前方最近的子块。
- 子列表在末尾新增条目，子引用在末尾新增段落；已有空输入位置会复用。表格、代码和数学块将光标定位到已有内容末尾。
- 有序列表从原起始编号继续编号，新建任务条目默认为未完成；已有任务状态保持。创建输入位置可以一次撤销和重做，纯光标跳转不增加历史记录。

## 插入嵌套块（1.1.0）

在所见即所得模式中，将光标放在列表条目或引用内的段落、标题上，右键选择 **在此层级嵌套块格式**，再选择要插入的格式。新块位于当前段落或标题之后，属于当前列表项或引用，不拆分已有文字，也不会跳到整篇文档的顶层。

例如，在 `父条目` 中插入无序列表并输入内容，保存后为：

```markdown
- 父条目
  - 子条目
- 另一个条目
```

在多层混合结构中，以光标所在的最近层级为准；在子列表条目里操作会继续增加子层级。在引用段落中选择引用块，可创建嵌套引用。

| 当前光标位置                                            | 可嵌套的格式                                       |
| ------------------------------------------------------- | -------------------------------------------------- |
| 有序列表、无序列表或任务列表的条目内                    | 表格、代码围栏、引用块、数学块、有序列表、无序列表 |
| 引用内的段落或标题                                      | 同上                                               |
| 顶层段落、表格单元格、代码内容、数学内容、HTML 等叶子块 | 菜单禁用                                           |
| 文字选区                                                | 菜单禁用；使用原有“将选中文字转换为”               |
| 源码模式                                                | 使用 Markdown 源码直接编辑                         |

数学块沿用项目现有的美元符号数学扩展，关闭该解析选项时隐藏入口。数学公式需输入内容；空的 `$$` 围栏按现有解析规则在重新解析时视为普通文本。

支持的容器依据 [CommonMark 容器块规则](https://spec.commonmark.org/0.31.2/#container-blocks)，表格和任务列表采用 [GFM 扩展](https://github.github.com/gfm/)。表格可以置于列表项或引用内部，但单元格只容纳行内内容，不支持继续嵌套块。

新菜单每次都会创建新块，包括与外层相同类型的列表或引用。原有 **在下方插入块／取消块格式** 继续负责整块之后的插入与取消格式；二者使用独立命令。

**取消格式也遵循当前层级。** 光标在嵌套列表或引用中时，取消离光标最近的匹配格式，只解除这一层；保留外层容器、兄弟条目及更深层的列表或引用。取消表格、代码或数学块时，内容变成所在层级内的普通段落。每次取消同样可以一次撤销或重做。

## 项目实现

| 层              | 位置与职责                                                                                                               |
| --------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Electron 主进程 | `packages/desktop/src/main/contextMenu/editor/index.ts`：复用六种块定义，构建原生子菜单，按上下文禁用                    |
| IPC             | `packages/desktop/src/shared/types/menu.ts`、`ipc.ts`：传递可嵌套类型与 `mt::cm-nest-block` 命令                         |
| Vue 渲染进程    | `packages/desktop/src/renderer/src/components/editorWithTabs/editor.vue`：保存右键时的选区、文档与版本，执行前恢复并校验 |
| Muya 引擎       | `packages/muya/src/block/contextActions.ts`：校验容器、插入当前层级、定位新块光标，统一撤销重做                          |

插入不改变原有列表序号、任务勾选状态、同级条目和后续块。菜单焦点切换后仍按右键时的选区执行；若已切换文档或文档内容已更新，则忽略过期操作。

## 定向验证

1.2.0 的层级键入由 `packages/muya/src/block/typingLevels.ts` 实现，经同一套右键选区快照和类型化 IPC 调用。对应 `typingLevels.spec.ts` 包含 16 项定向单元测试，`context-typing-levels.spec.ts` 包含 3 项真实 Electron 回归，覆盖菜单显隐、父子层级切换、Enter 连续键入、编号、任务状态、保存和撤销重做。

以下为 1.1.0 嵌套格式的回归文件：

- `packages/muya/src/__tests__/contextActions.nesting.spec.ts`：六种块 × 四种容器，混合嵌套、撤销重做、保存后重新解析与无效上下文。
- `packages/desktop/test/unit/specs/context-block-menu.spec.ts`：新旧菜单、命令、勾选和禁用状态。
- `packages/desktop/test/unit/specs/context-menu-locales.spec.ts`：所有界面语言均包含新增菜单文本。
- `packages/desktop/test/e2e/context-block-nesting.spec.ts`：真实 Electron 原生菜单调用、输入、保存、源码切换与嵌套引用。

本地通过 `pnpm install --frozen-lockfile --ignore-scripts` 准备依赖，复用已有相同 Electron ABI 的 `ced`、`keytar` 和 `native-keymap` 构建。不要为这次前端功能重新编译原生模块。云端在独立 Windows runner 上准备原生依赖并构建发行文件。
