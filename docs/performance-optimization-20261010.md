# 编辑器性能优化验证（2026-10-10）

## 修改内容

- 侧栏拖动时暂时固定编辑区宽度，松开后统一重排；避免每次指针移动都触发整篇文档换行及代码行号测量。
- 引用链接定义按文档修订缓存，避免每个段落渲染都复制、扫描全文。
- 消除新标签的重复加载；只在离开标签时保存撤销历史，恢复后释放额外副本；停止向响应式标签状态写入未使用的整篇块树。
- 解析结果使用 LRU 缓存，最多保留 3 份文档，按字符串与序列化状态估算限制为 8 MiB；超出预算的文档不缓存。修改解析选项会使缓存失效。
- 切换文档及销毁编辑器时释放块监听器、代码块 ResizeObserver、图表 MutationObserver、预览订阅及图片/公式缓存；过期图片加载结果不能回写新文档的缓存。
- 保持保存状态哈希格式兼容，以两个 32 位整数替代逐字符 BigInt 运算；不换行的代码行号使用固定行高，避免逐行读取 Range 布局。

## 测量结果

同一电脑、Edge 无头浏览器、1280 × 800 视口，使用 Muya E2E Vite 页面。文档含标题、粗体和引用链接。每组替换文档 3 次，统计同步加载、目录计算及之后两个动画帧的耗时中位数；包含重复加载缓存收益，不等同于应用启动时间。

| 内容规模                 | 修改前中位数 | 修改后中位数 | 耗时降低 |
| ------------------------ | -----------: | -----------: | -------: |
| 1,001 块 / 43,817 字符   |       680 ms |       322 ms |    52.6% |
| 3,001 块 / 133,617 字符  |     3,280 ms |       839 ms |    74.4% |
| 10,001 块 / 447,917 字符 |         未测 |     3,188 ms |        — |

替换 1,001 块文档再切回空文档，连续 10 轮：修改前 EventCenter 保留的 DOM 监听器净增 2,000 个，修改后净增 0 个。此结果验证了监听器泄漏修复；没有据此推算总内存下降百分比。缓存预算是估算大小，JavaScript 对象及浏览器自身缓存仍有额外开销。

原始数据：`performance-baseline-20261010.json`、`performance-results-20261010.json`。复测：先启动 `packages/muya/e2e` 的 Vite 服务到 `127.0.0.1:5174`，再从仓库根目录运行 `node scripts/performance/editor-benchmark.mjs`。默认使用已安装的 Edge，可通过 `PLAYWRIGHT_CHANNEL` 修改浏览器通道。

## 验证

- Muya 完整单元测试：287 个测试文件、2,476 项测试全部通过（`--testTimeout=15000 --maxWorkers=4`）。
- CommonMark / GFM 兼容性测试：4 个测试文件、1,347 项通过，保留现有规范兼容基线。
- 桌面完整单元测试：92 个测试文件通过、5 个跳过；1,048 项通过、39 项跳过。追加的保存状态哈希兼容测试及相关测试共 13 项通过。
- Electron 关键交互：侧栏拖动、大文档标签反复切换、光标和滚动恢复、撤销、标签关闭，共 12 项通过。
- 优化预览包实际启动并加载 1,000 个内容块成功；确认归档内主进程构建与本次产物一致，`ced.node` 已正确放入解包资源。
- Muya 与桌面 TypeScript 检查、Muya 循环依赖检查、生产构建通过；两个包的 ESLint 均无错误，仍有仓库已有警告。

渲染仍创建完整文档的 DOM。数万段落、复杂图表或大量图片的文档仍有相应渲染成本；本次没有引入文档虚拟化。

## 启动错误与预览包

回归测试首次启动时，开发依赖中的 `ced.node` 缺失，主进程加载编码检测模块时直接报错。当前电脑未安装 Visual Studio C++ 构建工具，`electron-rebuild -f` 无法完成。使用项目既有预览包中已编译的 `ced`、`keytar`、`native-keymap` 模块补齐开发依赖，随后在 Electron 42.1.0 / ABI 146 中确认加载成功，窗口回归测试也通过。

优化预览版位于 `dist/performance-preview/win-unpacked/marktext.exe`；应保留整个 `win-unpacked` 目录后运行，不能单独复制 exe。后续更换 Electron 版本时仍需按项目工作流重新编译原生依赖。

本机 electron-builder 的工作区依赖整理未能及时完成。预览包复用原预览版的 Electron 42 运行时及依赖，核对生产依赖和可选依赖声明完全一致后，将本次生产构建的 `out/` 写入新的 `app.asar`；原生模块与可执行依赖放在 `app.asar.unpacked`。
