# 项目梳理与文件夹优化

## 当前结构

项目是 pnpm monorepo，主要代码位于三个包：

| 包                 | 职责                                                                                |
| ------------------ | ----------------------------------------------------------------------------------- |
| `packages/desktop` | Electron 桌面应用，主进程负责文件系统，preload 提供类型化 IPC，Vue + Pinia 负责界面 |
| `packages/muya`    | 编辑器引擎，处理 Markdown 文档与编辑交互                                            |
| `packages/website` | React 网站，使用独立构建工具链                                                      |

本次改动集中在 desktop 的目录监听、project store 和侧边栏组件。Muya、依赖版本和现有原生模块没有改动。

## 问题与改动

此前打开项目会递归扫描整个目录，每个 Markdown 文件的新增事件还会调用正文加载器。文件逐条通过 IPC 传入界面，逐条查找、插入排序；数量较大时会放大 I/O、排序和 Vue 更新开销。即使子目录折叠，全部目录节点仍然保留在内存中。

现在根目录和首次展开的子目录各使用一个深度为 0 的 Chokidar 监听器。初始扫描只传递当前层级的元数据快照，使用现有统计信息，不读取正文；快照一次合并并排序。扫描完成后的文件变化按 40 ms 窗口批量传递。自然排序复用同一个 `Intl.Collator`。

侧边栏将已展开目录整理为固定 30 px 的行列表，只挂载视口附近的行，并在上下各保留 8 行缓冲。自动定位文件会先按需加载祖先目录，再滚动到对应行。组件卸载时移除事件总线订阅，避免滚动和切换项目不断积累监听函数。

文件夹标题右侧的关闭按钮和根目录右键菜单均提供“关闭文件夹”。关闭时清空目录、选择和输入状态，保存空的项目状态，并释放该项目的全部目录监听器；已打开标签及其文件监听器继续保留。切换项目也会释放旧项目的目录监听，迟到事件不会写入新项目。

已加载目录在折叠后仍继续监听，以保持缓存中的文件列表实时更新。搜索和快速打开继续使用原有 ripgrep，不依赖侧边栏已加载了哪些目录。正文仍由打开文件和标签监听流程读取。

## 验证

- 单元测试覆盖 5,000 个文件的快照和批量合并、加载去重、关闭时清理、迟到事件及深层文件定位。
- Electron E2E 使用含 4,001 个 Markdown 文件的临时项目，验证根目录只挂载约 30 行、滚动、按需定位、外部增删改、关闭后保留文件监听和重新打开。
- 回归覆盖折叠状态、新建文件、重命名、删除快捷键、焦点以及自动定位开关。
- Windows 测试使用精确标题定位路径，避免反斜杠被 CSS 选择器解释为转义字符。
- 使用现有 Electron 与原生模块完成编译和窗口测试，没有安装依赖或执行 `electron-rebuild`，无需 Visual Studio C++。

目录扫描耗时仍受磁盘、杀毒软件和网络文件系统影响；本次重点是限制扫描范围、取消正文预读，以及限制挂载组件数量。
